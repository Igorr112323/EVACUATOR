# «Эвакуатор»: Linux DXF-стенд, неделя 1

**Только учебная демонстрация. Это не nanoCAD-плагин, не проверка ГОСТ и не материал для реальной эвакуации.** Код, изображение и размеры знака, как и пределы R01, не сверены с официальным текстом: **[ПРОВЕРИТЬ ПО ТЕКСТУ ГОСТ]**. Знак E01-01 берётся из существующей в репозитории учебной базы `norms/gost_12_4_026_2015.json`, версия `0.1-demo`.

Стенд поддерживает **один** рецепт E01-01: Python-ядро строит нормализованную геометрию блока, `DxfBackend` записывает DXF, а рендерер заново открывает этот DXF и сохраняет PNG. Объект в DXF — обычный `BLOCK`/`INSERT`, а не пользовательский объект nanoCAD. Высота носителя задаётся равномерным масштабом вставки; изменение атрибутов DXF само по себе не запускает нормоконтроль.

## Запуск с нуля

Команды выполняются из корня репозитория; нужен Python **3.11** с `venv` и доступом к PyPI. Виртуальное окружение здесь создано вне репозитория и не включено в артефакты.

```bash
python3 -m venv linux_stand/.venv
linux_stand/.venv/bin/python -m pip install --index-url https://pypi.org/simple -r linux_stand/requirements-lock.txt
linux_stand/.venv/bin/python -m pip check
linux_stand/.venv/bin/python -m pytest -v linux_stand/tests
linux_stand/.venv/bin/python -m linux_stand demo --output-dir linux_stand/artifacts
linux_stand/.venv/bin/python -m linux_stand.verify_artifacts \
  --dxf linux_stand/artifacts/hello_e01_01.dxf \
  --png linux_stand/artifacts/hello_e01_01.png
```

Последняя проверка рассчитана **только на демонстрацию по умолчанию**: E01-01, высота 10 мм в модели, вставка `(0, 0)`, угол `0°`, печатный масштаб `1:1`. Она сравнивает данные с отдельно записанной [спецификацией](spec/hello_e01_01_h10.json); при других параметрах проверка по этой спецификации закономерно завершится ошибкой. При повторном запуске `demo` одноимённые DXF и PNG в указанном каталоге **перезаписываются**. Важные файлы сначала сохраните в другом каталоге.

Другие параметры, например:

```bash
linux_stand/.venv/bin/python -m linux_stand demo --height 12 --x 25 --y -10 --rotation 90 --output-dir /tmp/evacuator-demo-rotated
linux_stand/.venv/bin/python -m linux_stand demo --height 7 --output-dir /tmp/evacuator-demo-invalid
```

Второй пример завершится с кодом `2`, не создавая файлы: условная проверка R01 не пройдена. `--allow-invalid` явно разрешает записать не прошедший учебную проверку пример. `--scale 100` означает предполагаемую печать `1:100`: R01 сравнивает **высоту на бумаге = высота в модели / 100**, но печать, масштабирование принтером и реальный лист не проверяются. Единицы DXF (`$INSUNITS`) заданы в миллиметрах.

## Файлы и границы реализации

- `core/primitives.py`, `core/geometry.py`, `core/normcontrol.py`, `core/catalog.py` — ядро, работающее без импорта CAD-библиотек. Последний файл читает и проверяет только учебный E01-01 из текущего JSON. Ведомости, нумерация и другие рецепты в этой неделе не реализованы.
- `cad_backend.py` — контракт `ICadBackend`: слои, блок, линия, полилиния, текст, заливки, вставка и сохранение. `export.py` передаёт ему примитивы ядра.
- `dxf_backend.py` — проверенная запуском реализация на `ezdxf`. Пятиугольник триангулируется; заполнение головы аппроксимировано 32 треугольниками `SOLID`, точный контур дополнительно записан как `CIRCLE`. Поддерживаются только строго выпуклые невырожденные заливочные полигоны; остальные отвергаются.
- `renderer.py` — `ezdxf.addons.drawing` → Matplotlib Agg, без GUI; PNG строится **из сохранённого DXF**, а не из исходного объекта.
- `verify_artifacts.py` — отдельный читатель `dxfgrabber`, проверка координат, типов, слоёв и текста по фиксированной спецификации, а также проверка PNG через Pillow/NumPy. Поскольку `dxfgrabber` пропускает некоторые типы, например `HATCH`, отдельный простой сканер ASCII-групп DXF дополнительно считает все сущности в модели и нужном блоке. Он не является полной проверкой произвольного DXF. Растровая проверка — пороговая проверка цветов/размеров, **не** попиксельное сравнение с нормативным эталоном и не OCR.
- `tests/` — pytest, включая проверку граничных значений R01, масштаба, параметров блока, намеренно испорченных текста и геометрии, дополнительного `HATCH` и пустой картинки.
- `requirements.txt` — прямые зависимости; `requirements-lock.txt` — зафиксированные версии прямых и транзитивных зависимостей для этого Python-окружения. Lock не содержит хешей пакетов и не заменяет аудит безопасности/лицензий.

Настоящая реализация `MultiCADBackend` **[BLOCKED]**: проверенных host и MultiCAD SDK в среде нет. Python-код не исполняет существующее C#-ядро репозитория. Перенос или кодогенерация ядра в C# ещё не выполнены и не проверены; утверждение «для порта заменить только один backend-файл» пока не доказано. Риски и ручная проверка — в [отчёте](REPORT.md).
