# Подбор реальной среды nanoCAD — 28.10.2026

**Результат исследования: кандидат найден, готового и проверенного плагина «Эвакуатор» пока нет.** Этот документ не подтверждает сборку или работу в nanoCAD. Код прототипа в ходе исследования не менялся.

## Кандидат: Платформа nanoCAD 26

На [официальной странице продукта](https://nanocad.ru/products/platforma/download/) производитель предлагает пробную версию на 15 дней; для неё указаны регистрация в личном кабинете и штатная активация. На странице перечислены Windows 10/11 x64 и определённые редакции Astra Linux, Alt, РЕД ОС и AlterOS. Это кандидат для разработки, а не подтверждение совместимости нашего плагина с конкретной сборкой. При наличии у пользователя другой версии её нельзя без проверки заменять заявлением о совместимости с 26.

[Официальная страница API](https://www.nanocad.ru/developers/) описывает .NET и MultiCAD .NET для C#, включая пользовательские объекты, и указывает поддержку Linux. Точные сигнатуры, конфигурацию и совместимость host/SDK нужно подтвердить по поставляемым документации и примерам выбранной версии.

## Официальные библиотеки и SDK

Найдена [официальная инструкция по публичному серверу NuGet](https://docs.nanocad.ru/articles/#!nbim-sdk-24-1/ifce8336bf4de47f19bf22466cba6ae30). Она называет `https://nuget.nanodev.ru/nuget` и пакет `nanoCAD.Platform.NET` с **reference-библиотеками** `hostdbmgd.dll`, `hostmgd.dll`, `nrxgatemgd.dll`; в инструкции указано исключить runtime assets. Эти объявления помогают разрабатывать и собирать код, но **не являются запускаемым nanoCAD и не заменяют host-тест**; эта инструкция не подтверждает наличие всего MultiCAD SDK в данном пакете.

В [публичном индексе пакета](https://nuget.nanodev.ru/nuget/FindPackagesById()?id=%27nanoCAD.Platform.NET%27) 28.10.2026 отображалась версия `26.0.7226.4926` с группой `net60`. Пакет в текущую рабочую среду не загружался и сборка по нему не выполнялась. Версия NuGet-пакета и конкретная установленная сборка nanoCAD не объявляются автоматически совместимыми.

Полный SDK и примеры производитель предлагает через [Клуб разработчиков](https://developer.nanocad.ru/) после регистрации и оформления участия, см. также [страницу API](https://www.nanocad.ru/developers/). Условия доступа и передачи SDK определяет производитель. Ключи лицензий, пароли и персональные данные не нужны в чате или репозитории; SDK и DLL не следует коммитить.

## Пример на GitHub

[Evans-Sense/nanoCAD-MCP](https://github.com/Evans-Sense/nanoCAD-MCP) — сторонний проект под лицензией MIT; авторы позиционируют его как инструменты для nanoCAD 26. Рассмотрен снимок `45b2b6d6328b9ff1fe7a43a2e88cd39f03575844`. Его C#-проект нацелен на `net6.0-windows` и ссылается на локальный SDK nanoCAD 26; README отдельно упоминает SDK .NET 8 для сборки. Это **разные понятия** и не основание угадывать TFM для нашего плагина.

Проект — пример интеграции, а не плагин «Эвакуатор», не официальный SDK и не доказательство выполнения требований по знакам, DWG и нормативам. Он здесь не собирался и не запускался, бинарники и код не копировались. Повторное использование исходников допускается только после проверки условий всех соответствующих лицензий и совместимости с официальным SDK.

В ограниченном поиске GitHub не обнаружен готовый плагин, который бы подтверждённо закрывал данное ТЗ. Это не доказывает, что такого проекта нигде не существует.

## Почему полностью самостоятельная host-проверка пока невозможна

В текущем окружении Debian 12 не обнаружены nanoCAD, .NET SDK и GUI-дисплей; Debian 12 не указан в приведённом производителем списке поддерживаемых ОС. Команды `curl -I --max-time 10 https://nanocad.ru/developers/` и `curl -I --max-time 10 https://nuget.nanodev.ru/nuget` в рабочем контейнере вернули код **35** при установлении TLS-соединения: прямого доступа к этим сайтам из контейнера нет. Официальные страницы и метаданные изучены через инструмент просмотра веб-страниц, но это не загрузка программы или пакета в рабочую среду.

В этой сессии нет доступа к установленной программе на компьютере пользователя. Тесты H01–H25, загрузка плагина, DWG и PDF не выполнялись. Статус по-прежнему `BLOCKED`.

## Практический путь продолжения

1. Использовать установленный пользователем nanoCAD нужной версии или официальную пробную Платформу nanoCAD 26 на поддерживаемой ОС. Активация выполняется пользователем штатно.
2. Получить соответствующий выбранной версии SDK/примеры через официальный канал. Публичный NuGet может дать часть **reference**-библиотек, но для полного ТЗ нужно отдельно проверить доступность и условия MultiCAD SDK.
3. Если лицензия разрешает, предоставить необходимые файлы SDK и документации через поддерживаемую передачу файлов; без ключей, паролей и других секретов. Иначе сборку с использованием SDK можно выполнять локально по инструкции с передачей обезличенных логов.
4. Я могу разрабатывать и корректировать плагин в репозитории, но проверка реального GUI на пользовательском ПК потребует запуска пользователем и передачи результатов, если среда с запущенным nanoCAD не станет доступна инструментам агента.
5. После этого требуются действительные host-проверки команд, создания и повторного открытия DWG, интерфейса, undo/redo и PDF, а также нормативная сверка 30 знаков и R01–R07 специалистом. Публиковать или называть продукт проверенным до этих результатов нельзя.
