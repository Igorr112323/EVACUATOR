# Руководство: подключение реального nanoCAD SDK `[VERIFY_IN_NANOCAD_SDK]`

## Текущий статус
SDK DLL и установленный nanoCAD в среде отсутствовали. **Рабочего nanoCAD-плагина нет**: нет `McCustomBase`-наследников, нативных grips, регистрации команд, DWG-адаптера, ленты, CUIX, установщика или подтверждённого API. `src/Evakuator.CadAdapter/NanoCad/SdkGate.cs` — единственное платформенное место в исходниках; `#if NANOCAD_SDK` намеренно останавливает компиляцию. Не снимайте блокировку простым удалением `#error`: это не создаёт мост.

## Подготовка среды
1. Установить лицензированные nanoCAD и SDK одной и той же версии для целевой ОС. Зафиксировать номер сборки, разрядность, .NET/CLR и документацию именно этого SDK. Посмотреть реальные пути и версии `mapimgd.dll`, `hostdbmgd.dll`, `hostmgd.dll` и других зависимостей в лицензированном SDK; названия и необходимость каждой сборки проверить в документации, не скачивать DLL из неизвестных источников. Не коммитить проприетарные DLL.
2. Запустить `pwsh -File tools/sdk-preflight.ps1 -SdkDir 'C:\path\to\sdk' -OutputPath sdk-preflight.json`. Скрипт только проверяет присутствие имён, версии/хеши и записывает локальный отчёт; **не устанавливает и не регистрирует** плагин. При отсутствии DLL или моста возвращает ненулевой код. Отчёт может содержать локальные пути: не публикуйте его без проверки. В этой Linux-среде `pwsh` отсутствовал, поэтому скрипт не исполнялся; его необходимо отдельно проверить на целевой машине.
3. Сверить поддерживаемый target framework и вариант межпроцессной интеграции: решение сейчас `net10.0`, его загрузка в nanoCAD неизвестна. При необходимости вынести независимое ядро в поддерживаемый target или организовать отдельный сервис, не подменяя хостовые API. Изучить лицензирование и разрешённые способы распространения.

## Работа, которую ещё нужно выполнить
- `[VERIFY_IN_NANOCAD_SDK: HostMgd / registration]` По примерам **установленного** SDK установить правильную точку входа, регистрацию команд, работу с активным документом, блокировки, жизненный цикл палитры и очистку ресурсов. Имена будущих `EVAC_*` в `packaging/ribbon.template.xml` — только дизайн, не реализованные команды.
- `[VERIFY_IN_NANOCAD_SDK: CustomObjects / drawing]` Реализовать реальные типы пользовательских объектов на подтверждённом базовом классе, сохранение каждого поля, версионирование данных, миграцию и повторное открытие DWG. Использовать геометрические примитивы ядра; проверить точные сигнатуры рисования и трансформаций, единицы, UCS/WCS, вращение, слои и видимость.
- `[VERIFY_IN_NANOCAD_SDK: SmartGrips]` Сверить разрешённый способ ручек перемещения/поворота/размера/смены типа и события изменений, в т.ч. отмену, копирование, удаление, блоки и внешние ссылки.
- `[VERIFY_IN_NANOCAD_SDK: Serialization]` Проверить конкретные методы сериализации/десериализации выбранной версии, политику копирования, миграции и исходные данные; не копировать проприетарные примеры в этот репозиторий.
- `[VERIFY_IN_NANOCAD_SDK: transactions / undo]` Реализовать мост `ICadDocumentContext` с настоящими транзакциями/блокировкой документа и одной undo-операцией лечения, не затирать параллельные изменения. Проверить закрытие документа, read-only, повреждённые данные и отмену на каждой стадии.
- `[VERIFY_IN_NANOCAD_SDK: UI / deployment]` Проверить нативное размещение UI, поток интерфейса, x64, ресурсы, подпись, рабочие схемы ленты и упаковки в конкретном SDK. Файлы `packaging/*.template*` концептуальны и намеренно не являются загружаемыми манифестами.

## План подтверждения в хосте
Для каждой версии хоста: чистая сборка с настоящими ссылками; загрузка/выгрузка; вставка 30 знаков; передвижение/вращение/масштаб; основная/резервная полилиния и ручки; изменение базы; пересоздание легенды; проверка и одно действие undo; сохранение, закрытие и повторное открытие DWG; конфликт ревизий, аварии и откат; несколько документов; демонстрация на тестовой копии. Записать логи/версию SDK/хоста и добавить автоматизированные интеграционные тесты. До успешного завершения ни одна метка `[VERIFY_IN_NANOCAD_SDK]` не закрыта.

- [Публично доступный пример SDK 24](https://github.com/akshin-kuvshin/transformer-core/blob/main/NC_SDK_RU_24.0.6377.4326.7134/samples/Mgd/CustomObjects/TextInBox.cs) содержит сведения об интерфейсе сериализации, но имеет proprietary copyright; его код в проект не копировался.
